# Patches to PS2Recomp

`thirdparty/PS2Recomp` is a submodule at upstream commit `e5636981` of
[ran-j/PS2Recomp](https://github.com/ran-j/PS2Recomp). It stays at that commit;
`scripts/apply_patches.sh` applies the files in `ps2recomp/` to the checkout, in
name order, and skips a patch that is already applied. Lines added by this project
are marked `sor`. Some comments are in Italian.

To undo them: `git -C thirdparty/PS2Recomp checkout -- . && git -C thirdparty/PS2Recomp clean -fd`

| Patch | What it changes |
|---|---|
| `0001-iop-module-args-rpc-and-pacing.patch` | IOP modules start with `start(argc, argv)` as on the console (Capcom's sound driver `SNDDRVHD.IRX` needs it). `sceSifBindRpc` from the IOP to a game server marks the client as bound, and `sceSifCallRpc` from the IOP to the game clears the reply and finishes at once, without running the game's server. The IOP runs in packets of at least 512 cycles, and one instruction counts as 4 cycles: this took the game from a quarter of its speed to about the console's speed. Thread, RPC server and module lists for the debug report. |
| `0002-runtime-stacks-heap-display-and-reports.patch` | `PS2Runtime::setAsyncCallbackStackRegion`: the callback stacks started at the top of RAM, where this game keeps its main thread's stack, and overwrote it. `PS2Runtime::pinGuestHeap`: the runtime's heap stays in a fixed area, and the game's `SetupHeap` no longer moves it over the game's data. The image is always shown in 4:3. `SOR_FOTO`, `SOR_FOTO_OGNI` and `SOR_FOTO_VRAM` save frames during tests. Messages when the runtime stops. |
| `0003-gs-image-upload-and-interlaced-display.patch` | `sceGsExecLoadImage` and `sceGsExecStoreImage` multiplied the VRAM address by 8, so textures landed in the wrong place and the screen stayed black. With INT=1 and FFMD=1 the buffer has half of the display's lines: half are read and each one is shown twice. `SOR_FOTO_FBP` shows another buffer during tests. Draw counts for the debug report (`sorGsRapporto`). |
| `0004-pad-modes-and-scripted-keys.patch` | `scePadInfoMode` reports two modes, digital and analog: with only one the game says the analog controller is not connected. `SOR_TASTI` presses keys by itself during tests. |
| `0005-menu-images-64bit-branches-and-keyboard.patch` | The translator tested `BLTZ`, `BGEZ`, `BLEZ` and `BGTZ` on 32 bits only, while the EE's registers have 64: the game's software floating-point subtraction went wrong for some values (the volume 10 in Options was drawn off screen). `sceGsExecLoadImage` reads the game's real `sceGsLoadImage` packet. The VIF1 interpreter skips the NOP and DIRECT after an image header instead of taking them as data (Options and Load Game were black). `DrawTriangle` computes Z exactly (dots on the Options page). The keyboard works even with a controller connected, and the log says which controller it sees. `SOR_TASTI` accepts `m<seconds>:<key>` (seconds from the first skipped movie), and L1 and R1. Debug: `SOR_GIFDUMP`, `SOR_GIFDUMP_DA`, `SOR_DMADUMP`, `SOR_IMGDUMP`. |
| `0006-first-arena-3d-saves.patch` | Stage 2. The callbacks of `sceMpegDemuxPssRing` run inside the call, as on the console: queued, the video stream overran its buffer and overwrote the player's model. DMA chains are no longer cut at 4096 tags (the VIF kept a wrong `CYCLE` for the next frame). New threads start with `vf0` = (0,0,0,1). The VIF's V4-5 format widens 5 bits to 8 (bone weights in the character microcode were 8 times too small). `sceMcOpen` with `SCE_CREAT` alone creates the file, so saving works. With `SOR_TASTI`, a real controller is ignored, and the script can move the left stick (`ssu`, `sgiu`, `ssx`, `sdx`). Debug: `SOR_VU1DUMP`, `SOR_VIFDUMP`, `SOR_MPGDUMP`. |
| `0007-speed-keyboard-stick-and-sound.patch` | Speed: a VU1 that translates the microprograms into lists of operations (`vu/ps2_vu1_veloce.cpp`), fast drawing on several threads in bands of 16 lines (`gs/gs_bande.cpp`, in `gs_cpu_backend.cpp` a fast path for triangles and sprites), thread switches without C++ exceptions, 50 Hz in PAL, timers and IOP run in packets. Keyboard on the sticks (`ps2_pad.cpp`). Sound: a simulated SPU2 (`ps2xIOP/src/emulator/core/iop_spu2.*`) and a raylib audio stream; `SOR_MUTO=1` keeps it off the speakers. |
| `0008-full-speed-in-the-first-arena.patch` | Stage 5: full speed from the menu to the first fight at 50 Hz. The VIF and the VU1 run on a thread of their own, away from the game's thread. Depth is tested before the texture is read. Bands of 8 lines. Threads that wait sleep or give up the core, instead of spinning. Image uploads run at the start of a drawing segment when no primitive of the segment touches those pages, so they no longer stop the threads. Dedicated fast paths for the most common triangles and sprites. A new check closes the segment when two primitives write the same page with a different format or base, because the same memory then lands on different lines, so in different bands. The comparison with the original drawing code covers lines too. Debug: `SOR_GSCLASSI`, `SOR_GSSENZADISEGNO`, `SOR_GSCONFRONTO=3`. |
| `0009-save-settings-keys.patch` | Keyboard: W A S D move only the left stick, the arrow keys move both the D-pad and the left stick, F is L3 and O is R3. |
| `0010-sqrt-reads-ft.patch` | The translator took the value of `SQRT.S` from `fs`. On the PS2 it is in `ft`, and `fs` is 0 in all the 182 uses in this game: every distance computed this way was wrong, and the camera jumped close to the player. |
| `0011-cvtw-truncates-and-reverb.patch` | `CVT.W.S` rounded; on the PS2 it truncates and saturates (`ps2_fcvtw`, the same rule as PCSX2). Reverb in the simulated SPU2 chip, the same calculation as PCSX2 (`SPU2/Reverb.cpp`, `SPU2/ReverbResample.cpp`, GPL-3.0). Voice volumes are counted apart from the envelope, and the mix follows `MMIX` and `BVOL`. `SOR_SENZAECO` leaves the reverb out of the mix, for comparisons. `ps2xRuntime/CMakeLists.txt` can link a static FFmpeg from `SOR_FFMPEG_DIR` (off in this build). |
| `0012-iop-wmemcopy-and-input-volumes.patch` | The IOP's `_wmemcopy` and `_wmemset` counted in words; the count is in bytes (`SNDDRVHD.IRX` gives the same count to `memcpy`). Copying 4 times too much overwrote the driver's variables: one of its threads then used all the IOP's time and the music thread never ran. `AVOL`, `BVOL` and `EVOL` are plain signed 16 bits: doubled, the game's 0x7FFF became -2. The sound no longer runs past the end of an auto DMA block before the next piece arrives, which played short holes of silence. |
| `0013-movies-and-float-compares.patch` | The movies play. `sceMpegGetPicture` calls the no-data callback, as the library does on the console, and it runs as a new kind of guest call (`ThreadCall`) that lets interrupts through, because the callback spins until the vblank thread has read the next half buffer. `sceMpegDemuxPss` answers short only at the end code. The movie sound: the stream types were off by one (PCM is 2, ADPCM is 3), the SShd header says which one to call, and `IRQINFO` (0x7C2) tells libsd which core raised a voice interrupt. `sceVif1PkAddGsAD`, `sceVif1PkCloseGifTag` and `sceVif1PkOpenDirectCode` no longer refresh the size of the open DMA tag: the game's own translated code adds it when it closes the tag, so it came out doubled and the chain stopped after one image. Float compares (`C.EQ`, `C.LT`, `C.LE`) now work on sign and size like the EE, with no NaN: garbage read as a position by the lock-on code made `Adj_scr_line_check` write outside its grid and freeze the game after the First Match. |
| `0014-packet-builder-tag-size.patch` | The stubs of the game library's packet builder (`writePacketBuilderCurrent` in `Stubs/GS.cpp`) no longer refresh the size of the open DMA tag at each write: the game's own translated code adds it when it closes the tag. In areas with water, `classWATER_SURFACE_draw` came out with a doubled size, the DMA chain ran on into other memory and read the game's code as VIF commands: broken picture and 0-5 frames per second. The same fault as in `0013`, which had fixed it only in `sceVif1PkAddGsAD` and two others. |
| `0015-invocation-stacks-reused.patch` | `releaseInvocationStacks`: the 16 KB stacks used to call into the game from the runtime (64 of them in 1 MB) are given back when a thread is deleted and reused. They were never given back, so a long session ended with `EE invocation stack space exhausted`. |
| `0016-second-movie-sound-callbacks.patch` | `sceMpegCreate` now forgets the callbacks registered for the previous movie on the same object. The game does not always call `sceMpegDelete`, so from the second movie on each sound packet was handed to the game twice: the sound stream broke, the sound thread waited forever, and the screen stayed grey with a beep after the "City Arena" title card. |
| `0017-near-clipping-floor.patch` | The VU0 MAC flags. The game draws the parts of a model close to the camera through a separate path that clips them (bit 0x40 of the part, `classMODEL_BASE_make_scis_parts_trans`), and chooses that path from a sphere-against-view test that reads the MAC flags (`cfc2 $vi17` after `VMSUB`, in 22 places of 16 functions). No translated VU0 instruction wrote those flags, so they were always 0: the near parts were never drawn, and in the arenas a flat grey shape (the background) showed through the sand near the camera. `translateVU_VMSUB_Field` now writes them. The clipping microprograms use `BAL`, `JR` and `JALR`, which sent the whole program back to the VU1 interpreter (4 frames per second): the fast VU1 (`ps2_vu1_veloce.cpp`) now runs them, and looks up the target of a `JR` while it runs (if it is not the start of a block, the interpreter takes over). Debug: `SOR_VU1VERIFICA=N` starts the comparison after N seconds, `gstutti` in the test remote control writes every primitive of 4 frames to a file (`gs_bande.cpp`), `SOR_SPU_TRACCIA` traces the sound streams and the IOP interrupts. |
| `0018-video-card-renderer-and-wide-screens.patch` | The video card. `gs/gs_pcsx2_mirror.cpp` sends everything the game gives the GS to PCSX2's GS in `sor-gs.dll` (source in [`../sor-gs`](../sor-gs)), which draws inside the game's window with DirectX 11, DirectX 12 or Vulkan; the processor drawing is skipped then. The launcher chooses it (`SOR_GRAPHICS`); without `sor-gs.dll` nothing changes. VSYNC: when the screen's rate is a whole multiple of the game's, the game's clock follows the screen's (`sorGsPaceNs` in `EeScheduler.cpp`). The wide screens: a 16:9 or 21:9 window; the GS is told when the gameplay camera is in use and when a view stays 4:3 (the movies, `MPEG.cpp`; the pause and title menus and the game's own scenes, `pc/widescreen_gen.py`), so that only those get black bars and talks stay wide. F11 and Alt+Enter switch to full screen (`ps2_runtime.cpp`). The shadows: `sceDmaSendI` and the scratchpad DMA (channels 8 and 9) follow the interleave mode (MOD=2: TQWC qwords copied, then SQWC skipped), which this game uses for its shadows; as a normal chain the corners arrived shifted and long dark stripes joined the characters (`DMA.cpp`, `Support.h`, `ps2_memory.cpp`; `SOR_SHADOWFIX=0` brings the old behaviour back). The sound: the SPU2 makes its samples on the game's clock instead of the PC's, so the voices stay in time with the lips after the game stops for a moment (`iop_spu2.cpp`, `EeScheduler.cpp`; `SOR_AUDIO_ORA=1` brings the PC's clock back, `SOR_AUDIO_CODA=0` lets the speakers' queue grow as before). The controller: `SOR_PAD_SWAP`, `SOR_PAD_INVERT_X` and `SOR_PAD_INVERT_Y` (`ps2_pad.cpp`, set by the launcher's CONTROLS). `SOR_CDTEMPI=1` prints the reads from the disc image that take more than 2 ms. |
| `0019-version-2.5.patch` | The changes of 2.5 (see [CHANGELOG.md](../CHANGELOG.md)). |
| `0020-version-2.6.patch` | The changes of 2.6: the VU1 programs handed to `sor-vu.dll` (`runtime/sor_vu1_host.h`, source in `pc/sorvu` and `pc/kzvu`), a faster VIF unpack, the time measures of TIMINGS (`runtime/sor_times.h`, `SOR_TEMPI`), and the other fixes in [CHANGELOG.md](../CHANGELOG.md). |
| `0021-version-2.9.patch` | The changes of 2.7 to 2.9 in the runtime: the black box pictures taken from the video card (`gs_pcsx2_mirror`), the films a texture pack can replace, and the other fixes in [CHANGELOG.md](../CHANGELOG.md). |

Outside the patches, in `pc/`: `sor_hle.cpp` finds files by reading the disc image's
ISO9660 index, can skip the movies for tests (`SOR_SENZAFILMATI`): `classMOVIE_TASK::task_init` closes the task at once, and keeps the video mode in `settings.ini`; `main_sor.cpp` places the
stacks and the heap; `sor_profilo.cpp` is a sampling profiler (`SOR_PROFILO`, read with
`strumenti/profilo.py`). In `strumenti/stubs_da_analyzer.py`, `InitAlarm` is left to the
runtime: translated, it made every `SetAlarm` fail. `sceGsSetDefLoadImage`, instead, stays
translated: the game sends by itself the packet that function fills. `main_sor.cpp` also stops
Esc from closing the window: Esc is ○. `sceVu0*` also stay translated: the runtime's `sceVu0MulMatrix` multiplies in the opposite order from the original.

`widescreen_gen.py`, run by `compila_pc.sh` after each translation, writes three choices into the translated code: the wide camera (the values of PCSX2's widescreen patch for SLES-52950, by sergx12, widened again for 21:9), the 60 Hz start (`SOR_60HZ`: the game's video mode byte, 0x551402) and the steady picture (PCSX2's No-Interlacing patch for this disc, 0x1e9384; `SOR_INTERLACE=1` brings the original back). `sor_monitor_off.cpp` stands in for the monitor of my local test builds, which is not in this repository.

## Patches to PCSX2, for sor-gs.dll

`sor-gs/` is built inside a checkout of [PCSX2](https://github.com/PCSX2/pcsx2) at commit `1ccd6a8dc3574771c138849039d71951a3a1c175`. Steps: [sor-gs/README.md](../sor-gs/README.md).

| File | What it changes |
|---|---|
| `pcsx2/0001-sor-gs-in-pcsx2.patch` | Adds the `sor-gs` folder to PCSX2's `CMakeLists.txt`. Texture replacements find the game's serial without PCSX2's virtual machine: `sor-gs.dll` gives it in `SORGS_SERIAL` (`GSTextureReplacements.cpp`). Since 2.6: the video card's draw pipelines are written to a list in the cache folder (`sor_tfx_pipelines.bin`) and made at the start (DirectX 12, `GSDevice12.cpp`); the OSD is drawn without a virtual machine (`ImGuiManager.cpp`, `ImGuiOverlays.cpp`); time measures for TIMINGS (`GS/SorGsTimes.h`); smaller changes in `GSDevice`, `GSDevice11` and `GSRendererHW`. |
| `pcsx2/build-deps-sor.bat` | PCSX2's `build-dependencies.bat` without what the GS alone does not need (Qt, FFmpeg and the video encoders, KDDockWidgets), with `-products *` so that the Visual Studio Build Tools are found too, and a release build. |
